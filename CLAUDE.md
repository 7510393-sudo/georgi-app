# Chronotheca — правила работы

Дневник-планировщик для iPhone. Автор — один человек, живёт в Англии, пишет
по-русски, тестирует каждую сборку через TestFlight и присылает замечания
пронумерованным списком.

**Главный принцип:** записи — обычные файлы в папке, которую выбрал человек.
Приложение в этой папке гость: читает и пишет, но не прячет, не шифрует и
ничем не владеет. Удалили приложение — записи остались.

## Как разговаривать

- По-русски, простыми словами, без программистских терминов.
- Коротко, если не просят разбора. Итог — первой строкой.
- Честно: чего не проверил глазами — так и сказать.

## Как работать

- **Собирать только по слову «собери».** Сборка — это новый номер в
  `.github/release-trigger` (следующий — **60**), дальше TestFlight сам.
  Проверки идут на каждой отправке и без сборки.
- **Проверять перед отправкой.** Номер поднимается только после зелёной
  «Сборки iOS» (она гоняет `xcodebuild test`). Если менялся вид — сначала
  посмотреть снимки из симулятора (`docs/screens/`, их кладёт CI).
- Компилятора в облачной сессии нет: Swift пишется вслепую. Перед отправкой
  — сверить парность скобок; компилирует CI.
- Ждать CI экономно: одна проверка после того, как сборка точно кончилась.
  Прогон «Снимки экрана» отменяется новой отправкой — не отправлять, пока
  нужны его снимки.
- Apple пускает ограниченное число сборок в сутки (ошибка 90382).
- **Каждое решение — в `docs/04-decisions.md`** строкой с причиной
  (следующий номер — **P189**). Замечания по сборке — в
  `docs/NN-замечания-СБОРКА.md`.
- В сценариях сборки — только латинские имена переменных (bash их не
  понимает; проверяет `.github/проверить-сценарии.py`).
- Ключ App Store Connect (.p8) никогда не просить и не трогать: автор кладёт
  его в секреты GitHub сам.
- Ветка — `claude/diary-planner-competitor-analysis-51rayl`. PR не
  открывать, пока не попросят.

## Чего нельзя ломать

- **Сохранность записей.** Никогда не писать поверх файла, которого
  приложение не прочитало или который изменили в другом месте; файл сперва
  читать напрямую, облако спрашивать потом (P182–P184, P187). Проверки
  `StorageSafetyTests` обязаны оставаться зелёными.
- **Открытая и соседние страницы рисуются одним и тем же кодом** — иначе
  текст прыгает при перелистывании (P114; CI сличает снимки попиксельно).
- **Ничто не двигается само, кнопки не пропадают** (P113, концепция).
- **Название дела и ответ «Как прошло?» — одна строка в файле**: «Ввод»
  уводит дальше, а не переводит строку (P172, P180, P185).
- **Брать деньги за содержимое папки нельзя** — только за приложение (M14:
  месяц пробы, дальше £15 разово).
